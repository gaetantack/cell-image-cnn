## What each new file does, and why

### The split
- **`src/splits.py`** makes and reads the split.
  - *Stratified* means every phase is spread over train/val/test in the same proportions as in the whole dataset. Without this, a random split could by chance put all 15 anaphase cells in train and none in test.
  - `load_split("test")` deliberately raises an error unless you pass `final_test=True`. This is a safety lock, so no script can accidentally peek at the test cells before week 5.
- **`scripts/make_splits.py`** ran once and wrote `splits/splits.json`. It refuses to run again if the file exists, because the split must never change: otherwise results from different weeks would not be comparable.
- **`splits/splits.json`** lists, for each split, which rows of the dataset belong to it. A "row" is the position of a cell in the array that `load_dataset()` returns.
  - Train: 22,586 cells
  - Val: 4,840 cells
  - Test: 4,840 cells
- **`tests/test_splits.py`** checks four things:
  - no cell is in two splits, and every cell is in one;
  - the sizes are 70/15/15;
  - every class (both 4 and 7) appears in every split;
  - each class's share in each split is within 1 percentage point of its share overall.

### The hand-crafted features (for the random forest later)
- **`src/features.py`** turns each cell image into 32 numbers a random forest can use:
  - **Mask** (which pixels belong to the cell), made from the brightfield image.
  - **Shape (7):** area, perimeter, eccentricity (0 = circle, near 1 = elongated), solidity (how "un-dented" the outline is), long and short axis length, extent (how much of its bounding box the cell fills).
  - **Intensity (7 per channel):** mean, SD and the 10/25/50/75/90th percentiles of the pixel values *inside the mask*, for brightfield and darkfield.
  - **Texture (4 per channel):** GLCM features. A GLCM counts how often a pixel of brightness *a* sits next to a pixel of brightness *b*.
    - **Contrast:** neighbouring pixels differ a lot (grainy).
    - **Homogeneity:** neighbours are similar (smooth).
    - **Energy:** few repeated patterns dominate.
    - **Correlation:** brightness changes gradually and predictably.
  - **3 QC columns:** number of objects in the mask, how many border objects were removed, and whether the mask touches the edge. Plus `row`, `cell_id` and `label_7`.
- **`scripts/compute_features.py`** runs this on every cell (about 1 minute) and saves `data/features.parquet`. Parquet is a compact table format; `data/` is not in git, so rerun this script on a new computer.
- **`scripts/mask_check.py` → `figures/mask_check.png`** shows 20 random training cells with the mask outline drawn on both channels. Always look at a segmentation before trusting numbers computed from it.
- **`tests/test_features.py`** builds a fake "cell" (a dark ring with a bright inside on grey) and checks that the mask finds it, that a dark block in the corner is ignored, and that the features come out as numbers.
- **`src/config.py`** gained all the mask and texture settings, so they are in one place.

### Metrics and baselines
- **`src/evaluate.py`** computes, for any set of true and predicted labels:
  - **Macro-F1:** F1 per class, then a plain average, so G1 and anaphase count equally.
  - **Balanced accuracy:** the average of the per-class recalls.
  - **Per-class recall:** what fraction of the real anaphase cells were called anaphase.
  - **Confusion matrix:** as counts, and row-normalised so each row sums to 1 (read a row as "of the true G2 cells, X% were called S").
- **`tests/test_evaluate.py`** checks these against a small example worked out by hand.
- **`src/experiments.py`** appends one row per run to `results/experiments.csv`. It refuses to log a test-set result.
- **`scripts/run_baselines.py`** runs the two "know-nothing" classifiers, trained on train labels only and scored on val:
  - **Majority:** always guess G1.
  - **Stratified:** guess randomly, in the class proportions of the training set.

  Every real model must clearly beat these.

| Classes | Baseline | Macro-F1 (seeds 0/1/2) | Balanced accuracy |
|---|---|---|---|
| 4 | majority | 0.154 (identical for all seeds) | 0.250 |
| 4 | stratified | 0.258 / 0.262 / 0.250 | 0.258 / 0.262 / 0.250 |
| 7 | majority | 0.088 | 0.143 |
| 7 | stratified | 0.148 / 0.148 / 0.142 | 0.148 / 0.148 / 0.142 |

Balanced accuracy of a know-nothing classifier sits at 1/number of classes (1/4 = 0.25, 1/7 ≈ 0.14), which is what we see. That is the chance line for Fig 2.

## Decisions I made for you (please check)

1. **Branch, not `main`.** I pushed to a new branch `session-2026-10-24` instead of straight to `main`, so you can look before merging. To merge: `git switch main && git merge session-2026-10-24 && git push`.
2. **Separate commit for last session's EDA.** The uncommitted EDA files from last session got their own first commit.
3. **Split stratified on the 7 phases**, not the 4 classes. This automatically balances the 4-class split too, and keeps the rare phases spread out.
   - Test was split off first (15%), then val from the rest.
   - Val holds G1 2,150, S 1,293, G2 1,290, prophase 91, metaphase 10, anaphase 2, telophase 4.
4. **"Within 1%" means 1 percentage point.** I read your rule as within 1 percentage point of the overall share. For the rarest phases this is easy to pass, so the "every class in every split" test is the one that really protects them.
5. **The split test reads test-split *labels* (not images).** That is the only way to check "every class is in the test split". No test image is looked at, and nothing is trained or scored on it.
6. **Features computed for all cells, including test cells, as you asked.** Each cell's features use only that cell's own pixels, and nothing is learned across cells, so this leaks nothing. The rule to keep: the random forest (and any scaling or imputation) must be *fitted* on train rows only. If you want CLAUDE.md read even more strictly, I can drop the test rows from the parquet until week 5.
7. **Mask method:** Otsu on *how different each pixel is from the background*, not on raw brightfield brightness.
   - In brightfield the cell has a dark rim and a bright inside on a mid-grey background. Plain Otsu on brightness would cut through the middle of the cell.
   - Steps: estimate the background from the 3-px border ring → light blur → Otsu → close small gaps → fill holes → remove specks of 30 px or less → remove objects reaching into the 3-px border ring (corner artefacts; if nothing else is left, keep the biggest object).
   - The brightfield mask is reused for darkfield.
8. **Shape is measured on the whole mask as one region**, so a telophase cell with two daughters is measured as one "figure-8" object (high eccentricity), not as two cells.
9. **Texture settings:**
   - 32 grey levels, distance 1 pixel, averaged over 4 directions (0°, 45°, 90°, 135°).
   - Only pixel pairs inside the mask are counted, so the background does not dilute the cell's texture.
10. **Column names:** `axis_major_length` / `axis_minor_length` instead of `major_axis_length` / `minor_axis_length`. scikit-image renamed them; the old names will stop working.
11. **Installed `pyarrow` 25.0.0** into the `cell-image-cnn` environment (needed to write parquet) and pinned it in `environment.yml`.
12. **Baselines for both 4 and 7 classes.** The majority baseline gives the same answer for every seed (it has no randomness) but is logged 3 times so every model has 3 rows.
13. **Format of `experiments.csv`:**
    - Columns: `date, model, n_classes, eval_split, seed, settings, macro_f1, balanced_accuracy, recall, train_time_s`.
    - Per-class recall and settings are stored as small JSON text, because 4- and 7-class runs have different class names.
    - Rerunning `run_baselines.py` would add 12 more rows; delete duplicates by hand if that happens.
14. **Extra code you didn't ask for:** `tests/test_features.py` and `src/experiments.py`, plus `src/splits.py` holding the test-split lock.

## Things that looked odd

1. **Corner artefacts are common.** In 860 cells (2.7%) the mask found an extra object at the image border, e.g. a dark rectangle in the corner of G2 cell 37491. That is the same kind of thing as prophase cell 30439 from last session.
   - The rate is similar in G1/S/G2/prophase (2.1–2.7%), so it does not look class-specific.
   - I have not checked all 860 by eye. Worth a quick look for RQ5, and maybe a line in the Observations table.
2. **One cell has no mask at all:** G1 cell 12686 (row 3498, in train or val), so all its features are empty (NaN). The random forest step needs a rule for this: drop it, or fill the gaps.
3. **51 train/val cells have a mask under 150 px** (typical is ~500). They could be very small cells, debris, or failed masks; cell 968 from the EDA grid is an example. Worth a look before the random forest.
4. **The mask includes the dark halo around the cell in brightfield**, so "area" is cell + halo. This is consistent for all cells, so fine for comparing, but it is not the true cell size.
5. **The shape features already follow the biology**, which is reassuring.
   - Median area on train+val: G1 480 → S 570 → G2 668 → prophase 731 → telophase 835 px.
   - Telophase stands out with eccentricity 0.82 (others ~0.3) and lower solidity (0.92 vs 0.97), because the two daughters form one figure-8 mask.
6. **Telophase daughters almost never come out as two separate objects** (only 8 cells in the whole dataset have more than one object), because the daughters touch. So "number of objects" is not a division marker; eccentricity is.
7. **The `mask_touches_border` QC column is almost always False**, because border objects are now removed. It only becomes True in the rare fallback case. Harmless, but not very informative.
8. **Validation has only 2 anaphase and 4 telophase cells.** In the 7-class results, recall for those phases can only take values like 0, 0.5, 1 (anaphase) or 0, 0.25, 0.5, … (telophase). Treat those numbers as very rough. This supports today's 4-class decision.
9. **Still open from last session:** the darkfield (Ch6) background is brighter in G1 images than in other phases. The darkfield intensity features are raw (not background-corrected), so the random forest could pick up that shortcut too.

## Quiz

1. Why does the split have to be *stratified*, and what could go wrong for anaphase without it?
2. The majority baseline gets 44% plain accuracy on the 4-class problem but a balanced accuracy of only 0.25. Explain the difference in one or two sentences.
3. Why was Otsu applied to "difference from the background" instead of directly to the brightfield image?
4. Features were computed for test cells too. Why is that not leakage, and what step *would* cause leakage if done on all cells?
5. Telophase cells have a much higher eccentricity than G1 cells. Explain this from the biology and from how the mask is made.

<details>
<summary>Answers</summary>

1. With only 15 anaphase cells, a plain random split could put 0 or 1 in val or test, making their scores meaningless or impossible. Stratifying puts ~70/15/15% of each phase in each split.
2. Plain accuracy rewards getting the big class right: G1 is 44% of cells, so always saying G1 is right 44% of the time. Balanced accuracy averages the recall per class: G1 = 1, S = G2 = mitosis = 0, so (1+0+0+0)/4 = 0.25.
3. The cell has a dark rim *and* a bright interior on a mid-grey background. A single brightness cut-off would split the cell itself. Taking the absolute difference from the background makes both rim and interior "high" and the background "low", so one threshold separates cell from background.
4. Each cell's features use only its own pixels; no information from other cells (or from labels) goes in. Leakage would happen if something were *fitted* on all cells: for example a scaler or imputer, feature selection, or the random forest itself, using test rows.
5. In telophase the cell is splitting into two daughters, so the outline is a long figure-8 instead of a circle. The daughters touch, so the mask joins them into one elongated object, and eccentricity measures exactly that elongation.
